# Правила ручной вычитки `changelog.json`

Каждая версия патча лежит в `<version>/result/changelog.json`. Это **финальный, вычитанный вручную** файл (скрипт-генератор его не перезатирает — см. `src/backend/scripts/patches`). Черновик со «сырыми» значениями скрипт кладёт рядом в `draft.json`.

Ниже — правила, по которым «сырой» шаблон превращается в человекочитаемый текст. Правится **только поле `note`**. Поля `parameter`, `old_raw_value`, `new_raw_value` остаются как есть — это исходные данные.

## Языки

В каждом `note` — 4 языка: `ru`, `en`, `uk`, `cs`. Заполняются все четыре.

## 1. Простые параметры (предметы, `hero_notes`, `ability_notes`)

Шаблон содержит плейсхолдеры `{change_label}`, `{old_raw_value}`, `{new_raw_value}`. Их нужно раскрыть:

- `{old_raw_value}` / `{new_raw_value}` → подставить значения из соседних полей как есть.
- `{change_label}` → метка направления изменения:

| Направление | ru | en | uk | cs |
|---|---|---|---|---|
| уменьшение | уменьшен | decreased | зменшено | sníženo |
| увеличение | увеличен | increased | збільшено | zvýšeno |
| замена типа / флаг | изменён | changed | змінено | změněno |
| добавлен (было `null`) | добавлен | added | додано | přidáno |

Направление определяется по смыслу (баф/нерф), а не механически по числу. Пример: `attack_slow` `-35 → -25` — сила замедления **ослаблена**, значит «уменьшен».

Пример:
```json
"old_raw_value": "85", "new_raw_value": "75",
"note": { "ru": "Damage Return Active: уменьшен с 85 до 75", ... }
```

## 2. Таланты (`talent_notes`)

`old_raw_value` / `new_raw_value` — это объекты с полным текстом таланта на разных языках. Нельзя писать просто «увеличен» — нужно **найти конкретное изменившееся значение** и описать его полным текстом.

- **Изменилось число** → назвать параметр и указать «с … до …».
  `Талант 6: Уменьшение Длительности Hex уменьшено с 0.3/0.6 сек до 0.2/0.4 сек`
- **Изменилось два параметра** → оформлять двумя подпунктами, каждое изменение отдельной строкой (`\n• …`):
  ```
  Талант 2:
  • Уменьшение Затрат Маны Starbreaker увеличено с 30%/60% до 40%/80%
  • Восстановление Маны увеличено с 2/4 до 3/6
  ```
- **Добавили эффект** → формулировка «Теперь также …», а не «Добавлено …»:
  `Талант 3: Теперь также Уменьшает Затраты Маны Shard Blast на 50%`
- **Полная замена эффекта** → `… заменено на …` (`replaced with` / `замінено на` / `nahrazeno za`).
- **Изменился порог/условие** → `… теперь за каждые 55/45 Силы вместо 65/50`.

Названия способностей/талантов (Starbreaker, Shard Blast, Haunt и т.п.) не переводятся.

### Кавычки для старого/нового текста таланта

Структурные изменения талантов (перемещён / добавлен / удалён / заменён) генератор
оформляет автоматически, беря старый и новый текст таланта в кавычки «…»:
`«старый текст» заменено на «новый текст»`.

Если при вычитке попадается **одинокий талант, описанный полным текстом** (в
`old_raw_value` / `new_raw_value` лежит целиком старая и новая формулировка, а не число),
его старый и новый текст тоже нужно брать в кавычки «…» на каждом языке. Пример:

```
Талант 4: «Старая формулировка таланта» заменено на «Новая формулировка таланта»
```

## 3. Что удалять

- **Чисто локализационные правки** (изменился только текст описания, игровые значения те же — напр. `Attack Modifiers` → `Attack Effects`) — удалять запись целиком, в патчлог они не идут.
- Если после чистки у героя не осталось ни `hero_notes`, ни `abilities`, ни талантов — убрать и самого героя из массива `heroes`.

## 4. Структура (что кладёт генератор)

Генератор (`scripts/patches/renderChangelog.js`) сам расставляет:

- **Врождённые способности** (`Innate=1`). Изменение попадает в `abilities` героя (видно, в какой именно способности), а сама способность помечается `"innate": true`. В `hero_notes` остаются только настоящие базовые атрибуты.
- **Таланты** — «Талант N» выносится в отдельное поле `title` (объект `{ru,en,uk,cs}`, без двоеточия). Текст в `note` — чистый, без префикса. Иконка на фронте берётся по `talent_id` без `modifier_<hero>_`, а `title` показывает номер уровня.
- **Боссы** — способности из `neutrals/*` (напр. `neutrals/tiny_boss`) не принадлежат герою. Они уходят в отдельный массив `bosses: [{ boss_id, abilities: [...] }]`, а не в `heroes`.

## 5. Готовые формулировки отдельных параметров

Для параметров, которые плохо читаются шаблоном («X: изменено с A на B»), формулировки задаются в
`scripts/patches/parameterFormatters.js` (ключ — имя параметра). Функция получает `(old, new, type)`
и возвращает готовый `note {ru,en,uk,cs}` (или `null` — тогда обычный шаблон). Пример — `SpellDispellableType`:

- `SPELL_DISPELLABLE_YES → NO` → «Больше нельзя развеять»
- `SPELL_DISPELLABLE_NO → YES` → «Теперь можно развеять»

Новые параметры со спец-формулировкой добавляются туда же.

## 6. Формат файла

- Отступ 2 пробела, кодировка UTF-8, в конце файла перевод строки.
- Юникод (кириллица) хранится как есть, без `\uXXXX`-экранирования.
- Апострофы в украинском тексте — обычный ASCII `'` (Здоров'я, бар'єра).
